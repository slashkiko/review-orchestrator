# Cross-host E2E

`scripts/validate_host_e2e.py` requires a Codex *and* Claude Code result, the exact shared fixture, a canonical v4 snapshot, and all routing/ledger/gate/qualification artifacts before it can report passed contract validation. The pair must share `run_id`, fixture hash, and snapshot hash; the snapshot and ledger are validated using their production validators, while routing/gates/qualification are checked against their strict artifact contracts. All executable inventory gates must have one passed matching record. A dry-run, single host, missing component, invalid/qualified-mismatch artifact, or mismatched pair cannot claim a passed contract. Artifacts never retain full model output.

`scripts/run_host_smoke.py` is dry-run by default and emits `not_run`. A real discovery/runtime smoke requires a main-prepared shared fixture and explicit `--repo` whose `SKILL.md` matches the fixture manifest hash. The fixed adapters use the smallest configured tiers (Codex Luna/low; Claude Haiku/low with a fixed budget cap) and run against that repository: Codex receives a read-only sandbox, while Claude receives plan mode, Read, and only the exact manifest-hash command. Claude authentication is checked locally before model invocation. Missing CLI/authentication and timeout are `unavailable`; nonzero, malformed, missing-observation, or mismatched results are `failed`, and both return nonzero. Temporary storage contains schema and discarded raw response. This verifies contract consistency and actual host-process invocation, not review quality, complete orchestration, a cryptographic attestation, or tamper-proof provenance. Unit tests validate command construction and parsing without invoking real CLIs; real processes run only during an explicitly approved smoke.
