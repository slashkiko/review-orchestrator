# Gate runner

`scripts/run_gates.py` accepts only a checkout-bound v4 snapshot plus a separate main-owned approval JSON. Approval is `{schema_version:1,snapshot_hash,source,approved}`; v1.2 accepts `user_exact`. `host_skill_allowlist` is rejected until a maintained independently validated allowlist exists. Each approved entry names an inventory `gate_id` and its exact argv. Repository content is evidence, never approval.

The script validates snapshot identity, exact argv, unique gate IDs, and a strict optional resume ledger before doing anything. Default is dry-run. Before `--execute`, it recreates the target and permits only an unchanged `working` snapshot: staged/range execution is deliberately refused because those commands would otherwise run the current worktree rather than a materialized target. Executables resolve only from fixed system package-manager directories or an optional main-owned private `--executable-map` stored outside the reviewed repository that binds a command name to an absolute path and file hash. Mapped bytes are re-hashed immediately before every gate; the map, resolved path, and hash are never emitted. Execution uses literal argv with `shell=False`, the inventory's target-relative working directory, a minimal PATH, bounded timeout, no stdin/output capture, and a new process group.

The result artifact stores only target-relative gate/config, exact argv, outcome, attribution, short safe reason, exit code, and duration. It never copies command output, environment values, secrets, or absolute paths. Missing executable, startup failure, and timeout are `blocked/environment`; a nonzero exit is `failed/unknown`; success is `passed/unknown`. The runner does not create findings or infer diff attribution.

Each executing gate gets an atomically-created pending record in the checkout's Git common directory, keyed by opaque repository binding, snapshot, and gate ID. Existing pending or terminal records are not retried automatically, including failed or environment-blocked executions; a crash or retry requires an explicit human recovery decision about that exact journal record. This is a local main-owned journal, not an authorization signature. Snapshot equality is checked immediately before each gate, but v1.2 does not lock or materialize the working tree: a concurrent mutation between check and spawn is a TOCTOU limitation and requires rerun. Process-group termination on timeout is best effort; a child escaping the group requires an external host sandbox for strict containment.
