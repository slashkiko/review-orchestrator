# Cross-host E2E

`scripts/validate_host_e2e.py` requires a Codex *and* Claude Code result, the exact shared fixture, a canonical v4 snapshot, and all routing/ledger/gate/qualification artifacts before it can report passed contract validation. The pair must share `run_id`, fixture hash, and snapshot hash; the snapshot and ledger are validated using their production validators, while routing/gates/qualification are checked against their strict artifact contracts. All executable inventory gates must have one passed matching record. A dry-run, single host, missing component, invalid/qualified-mismatch artifact, or mismatched pair cannot claim a passed contract. Artifacts never retain full model output.

`scripts/run_host_smoke.py` is dry-run by default and emits `not_run`. A real discovery/runtime smoke requires a review-run-owner-prepared schema-v3 shared fixture and explicit `--repo` whose `SKILL.md` matches the fixture manifest hash. In addition to discovery and challenge hashes, the fixture supplies separate nested-owner and direct-worker challenges. The parent harness must create one nested owner, that owner must create the direct worker, and the worker must not create descendants. A passed host artifact requires exact evidence for that topology plus a harness-verified delegation trace; absent delegation, malformed or `not_evaluated` evidence, a worker created by the parent, or mismatched challenges fail closed.

The adapters inherit each host's configured model and effort and run against that repository. The artifact records the requested policy as `default`, not a claim about the actual model or effort. Claude retains a fixed budget cap. Codex uses the local `app-server --stdio` protocol with a read-only sandbox and raw response events. This requires a host version exposing `experimentalRawEvents`; unsupported protocol requests fail closed. The probe keeps its synthetic thread history because context-sharing subagents require a saved parent rollout. It does not change user settings. Only the started root thread and turn contribute tool evidence; child-thread events cannot substitute for root calls. The harness accepts its topology only when the root trace contains one successful owner spawn with a matching call/result ID and the final `list_agents` output contains the expected owner/worker path with no worker descendant. Claude receives plan mode and the `Agent`, `Read`, and `Bash` tools, with an allow rule for the exact manifest-hash command. The allow rule is not an independent prohibition of every other Bash command; the probe instructions constrain command use, and plan mode remains active. Its dynamically defined owner has only `Agent`; its dynamically defined worker has no tools and receives a challenge absent from the parent prompt. The harness accepts the topology only when the root event stream shows exactly one call to the owner type and the final response contains the hidden worker challenge. Claude authentication is checked locally before model invocation. The adapter preserves inherited home/config locations and OS login-session identity so this check and the model process use the same existing login; arbitrary loader/tool configuration is not forwarded. The smoke starts the CLI in its own process group and kills that group on timeout before reporting the result. Missing CLI/authentication and timeout are `unavailable`; nonzero, malformed, missing-observation, missing trace, or mismatched results are `failed`, and both return nonzero. Temporary storage contains schema and discarded raw event/response data; Codex also retains the synthetic session in its normal host history. This verifies contract consistency, actual host-process invocation, and the nested delegation topology, not review quality, complete orchestration, a cryptographic attestation, or tamper-proof provenance. Unit tests validate command construction, trace extraction, success parsing, and fail-closed parsing without invoking real CLIs; real processes run only during an explicitly approved smoke.
